# Trading research and operational evidence

- Treat prior chat, README headlines, and unlabeled CSVs as leads, not proof. For each material claim, inspect the source that can establish it and cite it in the reply. If it is missing, stale, or contradictory, say what you could verify and what remains unknown. Never invent prices, fills, metrics, sources, or test outcomes to complete an answer.
- For live status, check the deployed environment read-only: systemd and timestamped journals for service health; broker order/fill records or a reconciled journal for execution. Report the target, check time, and observed window. An active process or a `No signal` log does not prove the order path works. Distinguish testnet orders, paper trades, and real-money fills. Keep offline research off the VM; do not change the deployment or submit orders as part of a check.
- Label market inputs by venue, instrument, interval, date range, and type: actual venue data, proxy, or synthetic/modelled data. Disclose gaps, fallbacks, and estimated execution inputs. Never present underlying-stock candles as perp history, modeled option prices as historical quotes, or assumed fees, funding, collateral yield, or maker fills as observed. If a required input is unavailable, report the limitation or label the result as a scenario.
- Before reporting a backtest result, check that the executed code implements the claimed rules. Link evidence sufficient to reproduce it: script and arguments, code revision or local changes, data sources and actual evaluation dates, baseline and variant settings, and run output. An unexecuted script is a proposal, not a result. State the starting capital, currency, and execution assumptions; cross-check headline metrics against the equity curve and trade ledger. Historical CAGR is not an expected live return or weekly income.
- Compare variants against unchanged Config C on the same dates, starting capital, and execution assumptions. Use information available at decision time; keep a holdout untouched by rule selection before calling it out of sample. Test shared margin and risk constraints without double-counting capital. If claiming an overlay preserves Config C entries, compare the trade ledgers for blocked, delayed, or resized fills; separate risk buckets alone do not prove that.
